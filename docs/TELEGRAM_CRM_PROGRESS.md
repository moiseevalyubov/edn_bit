## Реализовано

- Отдельный провайдер `edna_telegram_<channel.id>` для каждого активного Telegram-канала. Регистрация, переименование и удаление при отключении используют существующую CRM-синхронизацию. Коды и настройки MAX сохраняются. MAX Bot не становится CRM-отправителем.
- Используется прежний `/crm/messages/send`: проверка application_token и портала, принадлежности provider/канала, действующей CRM-настройки и готовности провайдера. Сохраняются исходные bindings сделки/контакта и выбранный нормализованный телефон. Приём callback атомарно сохраняет сообщение и задачу; повтор не создаёт новую отправку.
- Текст до 4096 символов через `/api/v1/out-messages/telegram`, `to.type=PHONE`. Для MAX прежний предел 4000 и прежний адаптер. Ответы Открытой линии остаются TELEGRAM_ID. Вложения, username, рассылки и зеркалирование первого исходящего в Открытую линию не добавлены.
- Существующий CRM-worker сохраняет попытку до POST. Неопределённый исход не повторяется автоматически; подтверждённый отказ соединения и явный Telegram 429 допускают повтор с прежним outMessageId. HTTP 200 не превращается в SENT/DELIVERED. Несовпадающие ID отправки или возвращённый телефон дают uncertain.
- `/status/{webhook_token}` Telegram сначала сопоставляет requestId с CRM-отправкой того же канала/портала, затем с отправкой Открытой линии. CRM READ обновляет CRM-статус в delivered, не создаёт задачу прочтения/уведомления в постороннем Telegram-диалоге. Ранние, повторные и поздние статусы используют прежнюю CRM-модель.
- Схема БД и разрешения приложения не менялись. Используются уже существующие `messageservice` и `imopenlines`; CRM-разрешение для поиска или объединения контактов не добавлено.

## Включение на предпроде

Новый параметр `CRM_TELEGRAM_OUTREACH_ENABLED=1` включает только исходящее Telegram из CRM. По умолчанию `0`: прежние MAX/MAX Bot/CRM MAX и Telegram в Открытых линиях работают как раньше. Это не удалённый ранее `TELEGRAM_ENABLED`.

Прежние условия CRM MAX остаются: `CRM_OUTREACH_ENABLED=1`, ожидаемый CODE приложения, корректная авторизация установки и выданный `messageservice`. Новое разрешение существующей CRM MAX установке не нужно. Без `messageservice` исходящее CRM недоступно, Открытая линия продолжает работать.

После выкладки и установки нового параметра открыть приложение администратором: `/api/crm/prepare` подготовит Telegram-провайдер, фоновая очередь зарегистрирует отправителя. Проверить готовность в диагностике; не удалять приложение или существующие каналы. При отправке из сделки использовать штатный выбор получателя/номера и Telegram-отправителя с названием нужного канала. Штатная подпись «СМС» – ограничение интерфейса провайдера; отправка идёт в Telegram.

Остановка: установить `CRM_TELEGRAM_OUTREACH_ENABLED=0`. Worker перестаёт начинать Telegram CRM POST; сверка удаляет только Telegram CRM-провайдеры и завершает ещё не начатые CRM-отправки с ошибкой. Уже отправленные сообщения и поздние статусы сохраняются. Входящие/ответы Telegram в Открытой линии и CRM MAX не отключаются. Возврат на старый код вместо этого параметра не является проверенным способом остановки новой CRM-функции.

## Проверки

Изолированные тесты используют синтетические данные и запрещают реальные HTTP. Добавлены проверки телефонного контракта, границ длины, типов ошибок, CRM-статусов отдельно от Открытой линии, раннего READ, поздних статусов после отключения, принадлежности каналу, повторов, сбоев commit до/после HTTP, восстановления uncertain, двух Telegram-отправителей рядом с MAX и прежнего Telegram-диалога при появлении телефона. Проверки lifecycle покрывают регистрацию, переименование, остановку Telegram без изменения MAX и отсутствие messageservice.

Финальный прогон: **212 тестов OK без пропусков** с отдельной временной PostgreSQL 16 на loopback; сервер остановлен, временный каталог удалён. AST изменённых Python-файлов с грамматикой Python 3.11, Node UI-проверки и git diff --check – OK. Рабочая БД, .env и реальные API-ключи не использовались. Лог прогона хранится локально в `.git/telegram-crm-stage3-pg-tests.log`, не включать в коммит.

Проверки объединения реальных CRM-карточек автотестами не имитируются. Их результат остаётся открытым до пробы на портале.
