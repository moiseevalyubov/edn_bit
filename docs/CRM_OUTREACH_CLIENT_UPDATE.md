# Подключение отправки из CRM у существующего клиента

План на 06.11.2026 для примерно 15 текущих клиентов. Однократное открытие формы администратором допустимо по уточнению владельца. Автоподготовку без открытия формы в этот выпуск не добавляем. Код приложения в рамках исследования не менялся.

## Что должно быть готово у команды edna

1. Совместимый серверный код и настройки по [инструкции DevOps](RELEASE_22_DEVOPS.md).
2. Версия приложения с прежним imopenlines и новым messageservice, доступная для штатного обновления существующих установок. На скриншоте владельца пока только imopenlines. Получение scope не следует из одной серверной выкладки.
3. Проверка одной существующей установки: штатное обновление и необходимые подтверждения, выдача messageservice, открытие формы администратором, успешная подготовка без новых ключей/подключения каналов, одна реальная отправка и прежний обмен Открытой линии.

Текущая тестовая установка уже подтверждает отправку, статусы и жизненный цикл каналов после предоставления прав. Сам переход старой опубликованной версии на новый набор прав отдельно не подтверждён. До контрольной проверки не обещать точное название кнопки подтверждения или отсутствие дополнительных шагов Битрикса.

## Короткая инструкция администратору клиента

После сообщения команды edna о доступности обновления:

1. Откройте установленное приложение edna в своём Битрикс24 под администратором. Если Битрикс предложит обновление или подтверждение новых прав, пройдите штатный процесс. Точные шаги команда дополнит после контрольной проверки.
2. Один раз откройте форму настроек каналов приложения. После загрузки формы подготовка каналов продолжается в фоне без отдельного уведомления; держать форму открытой не нужно. Если показана ошибка прав или авторизации, передайте её поддержке.
3. Откройте заново карточку тестового клиента с телефоном, выберите приложение в разделе «Сообщение» и нужный MAX-канал в выборе отправителя под редактором.
4. Отправьте одно проверочное сообщение на собственный тестовый номер и подтвердите получение.

Ранее подключённые каналы не нужно отключать/подключать заново; ключи вводить повторно не нужно. Если форма показывает ошибку прав или авторизации, передайте поддержке её текст без ключей и токенов. Не удаляйте приложение для устранения ошибки.

## Что проверяет поддержка при проблеме

- `scope` с full=false должен подтверждать messageservice в контексте нужного приложения. Проверено через b24-dev-mcp: full=true показывает доступные в портале скоупы и не доказывает выданные приложению права.
- Подготовка проверяет отдельно авторизацию администратора формы и сохранённую серверную административную авторизацию. Если браузер получил новые права, а серверные учётные данные ещё нет, форма может показать блокирующее уведомление. Не заменять серверную авторизацию случайным токеном сотрудника и не отключать проверки.
- Проверить BITRIX_EXPECTED_APP_CODE, глобальный флаг, сохранённый application_token и состояние провайдеров. Не выводить секреты.
- Если `messageservice` ещё не выдан, открытие формы не исправляет отсутствие права. Установить точный штатный порядок обновления прав; безопасный обработчик новой авторизации при необходимости рассматривать отдельной задачей.
